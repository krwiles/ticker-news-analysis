Testing the search feature

The project's first tests — and proof, twice over, that a test that always passes isn't actually testing anything.

The payoff of every "inject it, don't import it" decision so far

Every fetch function (lesson 7) takes its externals as parameters — client, session_factory. split_today_recent (lesson 9) takes now as a parameter. None of that was for its own sake — this lesson is why. Every single test below passes in a fake or a test-database version of these, with zero changes to the application code: 

await fetch_and_persist_headlines("AAPL", session_factory=test_session_factory)
split_today_recent(headlines, now=datetime(2026, 1, 15, 4, 30, tzinfo=timezone.utc))

A real platform gap, found running the suite for the first time

The very first test run failed with ValueError: the greenlet library is required. SQLAlchemy's async engine needs greenlet, and it's normally pulled in transitively — but its dependency marker lists Linux's aarch64 for ARM, not macOS's own arm64 string. The Docker container (Linux) got it for free; this Mac, running pytest directly for the first time, didn't. Fixed by declaring greenlet as a direct dependency instead of trusting the transitive marker — SQLAlchemy's own docs recommend exactly this for cross-platform safety.

A pytest-asyncio pitfall: session-scoped engines don't survive test boundaries

A session-scoped async engine fixture crashed on the second test with RuntimeError: Event loop is closed. pytest-asyncio gives each test function its own event loop by default — an engine created on test 1's loop is orphaned by the time test 2 runs on a different one. Fixed by making the engine fixture function-scoped instead of fighting loop-scope configuration: 

@pytest.fixture  # not scope="session"
def test_session_factory():
    engine = create_async_engine(TEST_ASYNC_URL, pool_pre_ping=True)
    return async_sessionmaker(engine, expire_on_commit=False)

The real foreign key caught a lazy test fixture

A test helper inserted a Headline directly without a matching Company row first — and headlines.ticker's real foreign key (lesson 7) rejected it, exactly as it should. The fix was the test helper, not the constraint: 

await session.merge(Company(ticker=ticker))   # added -- the FK applies to test data too
session.add(Headline(...))

The lesson's actual point: proving a test can fail

The lesson 7 date-filter bug, reintroduced on purpose:

assert len(filings) == 1
AssertionError: assert 2 == 1

Caught immediately, and — checked deliberately — the other 16 tests stayed green while this one failed. Reverted, all 17 pass again.

A second, more honest discovery from the same exercise. A test named test_dst_aware_not_a_hardcoded_offset_winter_est was deliberately broken by swapping the real timezone for plain UTC — and it didn't fail. Its own now/headline pair happened to land on the same calendar date under either interpretation, so it only ever proved "some timezone exists," never "the correct one is used." A test with a name that overpromises is worse than an honest gap — it would have hidden a real DST bug behind a false sense of coverage. Fixed by constructing a pair that genuinely straddles the EST/EDT boundary (a wrong -4 pushes now into the next calendar day while leaving the headline on the previous one) — verified this version *does* fail against a hardcoded -4, then reverted.

Check your understanding

Q1. Why is test_session_factory function-scoped instead of session-scoped, even though that means recreating the engine for every single test?

Reveal answer

An async engine is bound to the event loop it was created on. pytest-asyncio gives each test its own loop by default, so a session-scoped engine becomes unusable ("Event loop is closed") the moment a second test tries to use it.

Q2. What did the broken DST test actually prove about the *original* version of that test, before it was strengthened?

Reveal answer

That its assertion would have passed under either the correct offset or a wrong one -- it was verifying "conversion happens," not "the correct EST/EDT offset is used." A passing test isn't proof of correctness by itself; it has to be shown capable of failing for the right reason too.
