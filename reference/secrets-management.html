Secrets management cheat sheet

One page: the ladder, the leak paths, the lifecycle, this repo's commands, and a glossary.

Storage ladder

RungGives youMissing
0 Source code—Everything
1 Env varsOut of git, per-deployProcess/log/inspect exposure; shared
2 Per-service files (this repo)Scoped grants, no env dumpsPlaintext, manual rotation/audit
3 Secrets managerEncryption, identity, audit, central rotationStill static
4 Dynamic credentialsPer-instance, leased, self-expiringRuntime fetch + infrastructure

Leak paths → counter

Leak pathCounter
Committed to gitGitignore + gitleaks (pre-commit and CI)
Baked into image / CI logInject at deploy time; never COPY .env; don't echo
Env vars visible everywhereMounted files, per-service grants
Printed by the app or a library (URLs, tracebacks)Credentials in headers, not URLs; quiet the logger; test it
Shared → big blast radiusLeast privilege per service
Long-livedRotate, expire, prefer short-lived
Abused through the appRate limits, login, provider spend caps

Lifecycle and incident order

Lifecycle: create → rotate → revoke → expire. If leaked: revoke → rotate → clean up → investigate.

This repo

scripts/init-secrets.sh                       # create ./secrets/ (hidden prompts, idempotent)
scripts/init-secrets.sh --from-env            # move keys out of .env, strip them, print nothing
scripts/init-secrets.sh --rotate NAME         # NAME = finnhub_api_key | openai_api_key | postgres_password
docker compose up -d --force-recreate worker  # secrets are read at container start

# Mounted at /run/secrets/<name>, read by pydantic-settings (secrets_dir)
# worker: postgres_password, finnhub_api_key, openai_api_key   api: postgres_password   ui: none
# Required at startup: worker → postgres_password, finnhub_api_key · api → postgres_password
# Optional: openai_api_key (sentiment degrades; api reads SENTIMENT_CONFIGURED instead)

Gotchas: env vars/.env outrank secrets_dir · an existing Postgres volume ignores a changed password file (use ALTER USER) · Settings() builds at import time, so fail-fast checks live in create_app() / worker startup · known remaining: MinIO/Milvus minioadmin, Redis has no password (ADR 0017).

Glossary

TermMeaning here
SecretA value whose exposure grants access. Fails the "could we open-source the repo?" test.
ConfigDeploy-specific but not confidential (SEC user-agent, Google client ID).
Blast radiusWhat an attacker gets from compromising one component.
Least privilegeEach component gets only the access it uses.
Rotation / revocationReplacing a secret on schedule / killing it immediately.
Lease / TTLA credential's built-in lifetime; expiry revokes it.
Dynamic secretA credential minted on demand, unique to one requester (Vault's database engine).
Fail fastRefuse to start without required config, with a clear message.
